## 2. 接收机在系统中的位置

接收机是机器人侧主控 `H417-R`，位于穿戴端 H417-W 和机器人执行层之间。

```text
H417-W 穿戴主控
      |
   nRF24L01+
      |
      v
H417-R 接收机
  |       |       |
  |       |       +--> 四轮底盘 -> 4 x C620
  |       |
  |       +----------> 左机械臂关节驱动器
  |
  +------------------> 右机械臂关节驱动器
```

接收机不直接把人体关节角映射为机器人关节角。它接收手部目标位置，经过坐标变换、缩放、工作空间限制、逆运动学、速度限制和安全检查后，再向机械臂和底盘输出控制目标。

## 3. 设计目标

接收机 H417-R 主要负责：

1. 接收穿戴主控通过 nRF24L01+ 发送的控制包。
2. 检查包版本、序号、新鲜度、模式和故障状态。
3. 将人体坐标系下的左手和右手目标位置转换到机器人坐标系。
4. 对目标位置进行缩放、偏置、工作空间和速度限制。
5. 对左右机械臂分别执行 IK。
6. 检查 IK 结果是否为有限值、是否越限、是否接近奇异点。
7. 对关节目标做速率和加速度限制。
8. 通过 CAN 分别控制左机械臂、右机械臂和底盘。
9. 接收底盘 C620 的转速、电流、角度和温度反馈。
10. 在无线超时、传感器异常、IK 无解或执行器故障时进入安全状态。

## 4. 设计基线硬件

| 模块 | 基线选型 | 说明 |
| --- | --- | --- |
| 主控 | CH32H417MEU6，QFN-88 | 双核 V5F+V3F，多路 CAN/SPI，第一版可先使用单核 |
| 无线 | nRF24L01+ | 单接收链路，负责接收穿戴端最新控制状态 |
| 左机械臂 CAN | CH32H417 CAN 通道 | 建议作为独立子系统 |
| 右机械臂 CAN | CH32H417 CAN 通道 | 建议与左臂隔离 |
| 底盘 CAN | CH32H417 CAN 通道 | 与 C620 电调通信 |
| 底盘电机 | 4 x C620 | 控制 ID `0x200`，反馈 ID `0x201~0x204` |
| 调试 | SWD | 下载、在线调试和故障恢复 |
| 电源 | 按机器人电池母线设计 | 具体输入范围尚未在接收机原理图中冻结 |

注意：CH32H417 的多路 CAN 资源是设计目标，但具体引脚复用必须等原理图评审后冻结。

## 5. 推荐功能分区

```text
+------------------------------------------------------+
|                     H417-R Main                      |
|                                                      |
|  Power In -> Protection -> Buck/LDO -> 3V3/DVDD      |
|                                                      |
|  nRF24 SPI  ---- H417 ---- CAN1 -> Left Arm          |
|  SWD/Debug          |---- CAN2 -> Right Arm          |
|  Status LEDs        |---- CAN3 -> C620 Chassis       |
|  Buzzer/Button      |---- UART/USB -> Diagnostics    |
|                     |---- Reserved SPI/I2C/Display   |
+------------------------------------------------------+
```

如果 H417 的 CAN 数量或引脚复用无法同时满足所有子系统，应在原理图阶段重新划分通道，而不是在固件中进行不确定的软件分时复用。

## 6. 推荐接口定义

以下接口是当前基线，最终以正式 SCH 为准。

| 接口 | 建议方向 | 用途 | 最低要求 |
| --- | --- | --- | --- |
| `RF_CE` | H417 -> nRF24 | 无线使能 | 普通 GPIO |
| `RF_CSN` | H417 -> nRF24 | SPI 片选 | 支持高频 GPIO |
| `RF_SCK/MISO/MOSI` | 双向 | nRF24 SPI | 硬件 SPI |
| `RF_IRQ` | nRF24 -> H417 | 收包中断 | EXTI，可选 |
| `CAN1_H/L` | 双向 | 左机械臂 | 120 Ω 终端按总线位置配置 |
| `CAN2_H/L` | 双向 | 右机械臂 | 独立总线或隔离拓扑 |
| `CAN3_H/L` | 双向 | 底盘 C620 | 与四电机及终端电阻形成正确总线 |
| `SWDIO/SWCLK` | 双向 | 下载调试 | 5P 或 4P 标准接口 |
| `NRST` | 输入 | 复位 | 建议引出 |
| `BOOT0` | 输入 | 启动模式 | 建议预留跳线/按键 |
| `STATUS_LED` | 输出 | 电源、链路、故障 | 至少电源和状态灯 |
| `BUZZER` | 输出 | 报警 | 可选，建议预留 |

### 6.1 CAN 设计注意事项

- 每条 CAN 总线两端只能各有一个 `120 Ω` 终端电阻。
- 机械臂和底盘建议使用独立 CAN 总线，避免一个节点故障拖垮全部控制。
- CANH/CANL 应使用双绞线，并保持较短的支线长度。
- 接口应加入共模电感、TVS 和必要的共模/差模保护。
- 电机和机械臂线束应按大电流回路与信号回路分开布线。
- C620 与接收机必须共地；如果使用隔离 CAN，需要重新定义地参考。

## 7. 无线数据流

穿戴端发送的数据包建议包含：

```text
version
packet_type
sequence
X_L, Y_L, Z_L
X_R, Y_R, Z_R
roll, pitch, yaw_relative
joy_Lx, joy_Ly
joy_Rx, joy_Ry
mode
safety/status
```

接收机处理顺序：

1. 读取 nRF24 原始包。
2. 检查硬件 CRC 和地址过滤结果。
3. 检查版本号。
4. 检查 16-bit sequence 是否比上一帧更新。
5. 检查模式和安全状态。
6. 检查数据是否为 NaN/Inf。
7. 更新“最新有效目标”。
8. 超过无线超时阈值后停止更新目标。

接收机不能仅凭“收到过一包”就持续输出运动，必须判断数据是否仍然新鲜。

## 8. 从人体目标到机械臂关节

推荐处理链：

```text
p_hand_body
   -> body-to-robot 坐标变换
   -> scale / offset
   -> workspace limiter
   -> left/right IK
   -> finite and limit check
   -> rate limiter
   -> q_target
   -> CAN joint controller
```

IK 推荐原则：

- 使用上一周期关节角作为 seed。
- 优先选择解析 IK；复杂结构使用阻尼最小二乘数值 IK。
- 同时检查关节硬限位、软件限位、速度和加速度。
- 接近奇异点时增大阻尼并降低速度。
- IK 无解时保持上一安全目标，不允许 NaN 或越界值下发。
- 双臂先独立求解，再进行工作空间或碰撞耦合检查。

## 9. 底盘控制

上层只输出与具体底盘类型无关的命令：

```text
vx
vy
wz
```

如果底盘只能前后和旋转，则 `vy` 不参与运动学计算。

```text
joystick -> vx/vy/wz -> wheel kinematics -> wheel targets
                              |
                              +-> CAN -> 4 x C620
```

C620 基线：

| 项目 | CAN ID/字段 |
| --- | --- |
| 四路电流控制 | `0x200` |
| 控制范围 | `-16384 ~ +16384`，对应约 `-20 ~ +20 A` |
| 1 号反馈 | `0x201` |
| 2 号反馈 | `0x202` |
| 3 号反馈 | `0x203` |
| 4 号反馈 | `0x204` |
| 反馈内容 | 机械角、转速、转矩电流、温度 |

## 10. 状态机和安全动作

建议状态：

```text
BOOT
  -> SELF_TEST
  -> WAIT_LINK
  -> READY
  -> ARMED
  -> FOLLOWING
  -> CLUTCH
  -> SAFE_STOP
  -> FAULT
```

故障处理：

| 故障 | 检测条件 | 动作 |
| --- | --- | --- |
| RF 超时 | 无新序号超过阈值 | 冻结目标并进入安全停止 |
| 数据非法 | NaN、Inf、版本错误、范围异常 | 丢弃该包 |
| IK 无解 | 迭代失败、越限、条件数过大 | 保持上一安全目标 |
| CAN 掉线 | 心跳或反馈超时 | 对应子系统停机 |
| C620 异常 | 过温、反馈异常、通信丢失 | 底盘降级或停止 |
| MCU 卡死 | 独立看门狗超时 | 复位后进入 FAULT，不自动恢复运动 |

## 11. 固件模块边界

```text
firmware/h417_receiver/
  drivers/
    nrf24.c
    can_chassis.c
    can_arm_l.c
    can_arm_r.c
  motion/
    coordinate_transform.c
    ik_left.c
    ik_right.c
    chassis.c
  safety/
    supervisor.c
  app/
    receiver.c
```

实时任务中禁止：

- 动态内存分配。
- 阻塞式长时间等待。
- 高频 `printf`。
- 在中断中运行完整 IK。
- 在通信接收任务中直接写电机命令。

## 12. 推荐上电顺序

1. 电源保护电路稳定输出。
2. MCU 复位正常，时钟和 SWD 可用。
3. nRF24 自检通过。
4. 三条 CAN 总线初始化。
5. 检查机械臂和 C620 心跳。
6. 建立无线链路。
7. 状态进入 `READY`。
8. 操作员按下 Deadman/使能后进入 `ARMED`。
9. 收到有效目标后进入 `FOLLOWING`。
