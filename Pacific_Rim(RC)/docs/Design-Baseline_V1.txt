2. MCU选型
本项目的MCU种类收敛为两类：CH32L103与CH32H417。这样既满足成本/BOM简洁，又让主控保留足够的算力和外设余量。
[S1] WCH/OpenWCH CH32H417资料：双核V5F+V3F、V5F最高400 MHz、896 KB SRAM、960 KB Flash、3路CAN、4路SPI等。
[S2] WCH CH32L103资料：96 MHz、64 KB Flash、20 KB SRAM、ADC、定时器、2×SPI、4×USART、1×CAN等。


3. 传感器选型
[S3] TDK InvenSense ICM-42688-P：6轴、1.71~3.6 V、SPI/I²C/I3C、2 KB FIFO，陀螺/加速度量程可编程。
[S4] Bosch Sensortec BMI270：面向wearable的6轴IMU，1.7~3.6 V VDD、1.2~3.6 V VDDIO，支持SPI/I²C，陀螺最高6.4 kHz ODR。


4. KTH5502节点设计
KTH采集节点的目标是把每侧3个角度传感器做成一个独立、时间一致、故障可诊断的智能节点。中央H417只接收标准化的q1/q2/q3，不需要知道KTH到底是AB还是SPI。
KTH5502 每颗典型逻辑：

MODE=0  -> AB：A/B -> L103定时器Encoder模式
MODE=1  -> 数字接口：SPI 3线 / I2C

三线SPI：SCK + DATA(双向) + CS
SPI Mode 3，最高5 MHz

第一版固件建议：
1. 上电等待传感器内部初始化完成；
2. 启动AB输出；
3. 每1 ms读取/锁存三个定时器计数；
4. 需要绝对值时，在低速/静止窗口执行数字读取；
5. 绝对值与AB计数建立新的参考关系；
6. 回到AB连续跟踪。
[S5] 用户提供的KTH5502系列数据手册：MODE低=AB正交；MODE高=I²C/SPI；SPI为三线、Mode 3、最高5 MHz；数字角度16 bit；上电初始化期间禁止通信；AB最高1024线/圈的订货型号为KTH5502LVPSP8-AB1024。

6. CAN逻辑架构（不指定收发器型号）
本节只定义总线在系统中的角色和协议层，CAN PHY器件由后续评审。穿戴端建议所有L103与H417-W共用一条CAN逻辑总线；接收端H417-R则利用其多路CAN资源，把底盘、左臂、右臂按子系统隔离。
穿戴端 CAN：

0x101  左侧关节节点  q1 q2 q3 status seq
0x102  右侧关节节点  q4 q5 q6 status seq
0x111  左手输入节点  JoyX JoyY Buttons status seq
0x112  右手输入节点  JoyX JoyY Buttons status seq
0x120  H417系统状态    mode link sensor fault ...
0x121  H417时间/同步    timestamp / sync marker

建议：标准11-bit ID；节点上线后先发送版本/设备类型；
任何控制数据都带seq或timestamp，H417丢弃旧数据。

9. 人体正运动学、坐标系与离合/跟随
人体侧只有3 DOF/臂，因此首先输出位置XYZ最自然。接收端机械臂结构不同，因此使用笛卡尔空间复现，而不是关节角直接映射。
人体侧：
q1, q2, q3  --FK-->  p_hand = [x, y, z]^T (body/shoulder frame)

若考虑身体整体相对机器人方向：
p_robot_frame = R_body_to_robot * p_body + t_body_to_robot

离合（推荐）：
进入跟随：记录 p_hand_ref 与 p_robot_ref
跟随中：
    p_robot_cmd = p_robot_ref + S * (p_hand - p_hand_ref)
离合中：保持 p_robot_cmd 不变
再次接合：更新 p_hand_ref = 当前手位置，p_robot_ref = 当前机器人命令
然后继续跟随。


10. 双机械臂IK策略
接收机应建立一个与具体机械臂驱动无关的“目标关节接口”：上层只产生q_target[i]、dq_limit[i]、mode等，底层再根据实际执行器实现。
推荐的IK循环：

  1. p_des = mapping(hand_xyz)
  2. q_seed = q_prev
  3. solve IK(p_des, q_seed)
  4. check finite / joint limits / workspace
  5. check |dq| and |ddq|
  6. if valid:
        q_cmd = rate_limited(q_solution)
     else:
        q_cmd = previous_safe_cmd
  7. send to low-level joint controller


11. 接收机底盘控制
底盘部分不要让上层直接操纵4个电机编号。推荐定义一个抽象的底盘接口：vx、vy（如果机械结构支持横移）、wz。若底盘只有前后+原地旋转，则使用vx、wz。具体四轮运动学由底盘类型决定。
遥控层：
Joystick -> vx_cmd, vy_cmd(optional), wz_cmd

底盘层：
[vx_cmd, vy_cmd, wz_cmd]
        |
        +--> wheel_kinematics --> w1,w2,w3,w4
                                   |
                                   +--> motor controller

C620反馈：
ID 0x201~0x204 -> rotor angle / speed / torque current / temperature
控制：
ID 0x200 -> 1~4号电调目标电流
[S6] 用户提供的 RoboMaster C620无刷电机调速器使用说明：CAN控制/反馈格式及4路C620使用方式。


12. nRF24无线链路与2.4 GHz共存
场上存在其他2.4 GHz设备时，系统设计不能只依赖“地址不同”。地址只解决报文识别，真正需要处理的是同频/邻频占用、碰撞和重传。无线电只放在H417中央主控，避免左右节点各自形成独立2.4 GHz发射源。
建议应用层包（32 Bytes以内）：

byte 0   version
byte 1   packet_type
byte 2-3 seq
byte 4-5  X_L
byte 6-7  Y_L
byte 8-9  Z_L
byte 10-11 X_R
byte 12-13 Y_R
byte 14-15 Z_R
byte 16-17 roll
byte 18-19 pitch
byte 20-21 yaw_relative
byte 22-23 joy_Lx
byte 24-25 joy_Ly
byte 26-27 joy_Rx
byte 28-29 joy_Ry
byte 30    mode
byte 31    safety/status

nRF24硬件CRC/ACK用于链路层；seq用于应用层新鲜度判断。
[S7] Nordic nRF24L01 Product Specification v2.0：支持250 kbps/1 Mbps/2 Mbps、1 MHz信道步进、自动ACK和自动重传。

14. 标定流程
推荐首次上电标定流程：

1. 所有节点启动 -> CAN注册
2. KTH节点确认3路传感器在线
3. 读取/验证绝对角（若此版本启用SPI校准）
4. 读取IMU并做静止bias采样
5. 手部摇杆自动中心校准
6. H417-W等待“人体姿态基准”按钮
7. 保存当前人体关节/IMU参考
8. 接收机H417-R做机器人关节零位检查
9. READY -> 等待Deadman/Follow按键
15. 固件实现注意事项
不要在1 kHz实时任务里调用大量printf、动态内存分配或阻塞式延时；调试日志使用环形缓冲区，低频发送。
所有外部输入都要做单位转换、范围检查和有限数检查（finite）；禁止NaN/Inf进入IK或电机命令。
CAN/RF接收与算法计算之间采用双缓冲或“latest value”结构，不要让实时任务等待通信。
KTH AB计数使用硬件定时器；速度计算使用定时采样和时间戳，不用GPIO EXTI逐边沿计数。
绝对角读取的CRC必须验证；KTH传感器上电初始化窗口内不要提前通信。
所有参数分版本存储，并加CRC/校验；参数升级失败回退默认值。
H417第一版先单核；第二核启用前先定义清晰的共享数据结构和核间通信协议。
不要直接把人体关节角映射给机器人关节；所有机器人控制目标统一经过坐标映射 + IK + 限速。
无线数据包必须包含seq和mode/safety状态；接收机不能只看“有没有收到包”，还要判断是不是最新包。
对两个机械臂分别建立“目标位置”和“当前安全目标”的双变量，故障时不能把新目标清零造成突跳。

20. 冻结前必须确认的事项
确认KTH5502LVPSP8-AB1024的最终供应商、封装、磁铁规格以及对应料号的完整电气/磁场指标；当前用户提供文件主体是AB256系列资料，订货表列出了AB1024型号，因此不要直接把AB256的全部性能数字无条件套到AB1024上。
验证L103所选封装的3路Encoder Timer具体引脚复用，形成原理图级pin map；同时确认CAN和调试接口不会产生冲突。
确定H417MEU6是否能够满足最终穿戴主控和接收机所有I/O需求；若接收机要同时使用3路CAN+多个显示/机械臂接口，再做一次pin mux冻结。
确认机械臂自由度、关节类型、零位、限位、减速比以及执行器通信接口；这些决定IK模型和H417-R的3路CAN如何分配。
确认底盘是差速/滑移转向还是全向/麦轮；目前只定义上层vx/vy/wz抽象接口，不假设具体轮型。
确认比赛无线频谱规则、允许信道和发射功率；据此冻结nRF24信道策略。
确认是否需要长期绝对Yaw；若不需要，维持6轴IMU+相对Yaw。

本版本的核心结论 / 1) 全系统只保留两类MCU：CH32L103负责分布式采集/手部输入，CH32H417负责高层运动学、姿态、离合、无线以及接收机控制。 / 2) 每侧采用两颗L103：一颗在手部负责摇杆/按钮，一颗在该侧关节附近负责3颗KTH5502。 / 3) KTH节点默认以AB1024为运行时位置反馈，绝对角度SPI保留为初始化/校准/故障恢复手段。 / 4) 手部XYZ由H417统一解算，不在L103上做机器人层面的坐标逻辑。 / 5) 接收机采用H417；左右机械臂采用“笛卡尔目标 + IK”而不是人体关节角一一映射。

关于“6轴IMU能不能直接给绝对Yaw” / 不能长期稳定地给出绝对Yaw。加速度计可以把Roll/Pitch绑定到重力方向，但Yaw会随陀螺零偏积分而漂移。因此第一版建议把Yaw定义成“进入跟随/重新接合时的相对航向”，允许离合时重置参考。只有比赛需求明确要求长期绝对航向时，才再引入磁力计或其他外部航向参考。


项目 | 设计基线 | 固件要求
运行位置反馈 | AB1024 + 定时器正交计数 | 使用硬件Encoder/Counter，不用GPIO中断逐边沿处理
采样周期 | 1 kHz作为基础周期 | 每1 ms锁存3路计数、计算角度/速度并更新CAN数据影子区
角度单位 | 内部推荐Q16.16或0.01°定点 | CAN线上建议0.01°的int16；内部计算保留更高精度
速度 | Δcount/Δt + 一阶低通 | 高速时避免差分噪声；低速可延长差分窗口
绝对角 | 三线SPI，Mode 3，最高5 MHz | 封装在sensor driver内；回读后做CRC8/ITU检查
MODE切换 | 第一版不依赖动态热切换 | 资料明确给出MODE复用，但未给出运行中切换的完整时序；量产前需厂家确认。R1先用AB连续工作，绝对角用于上电/校准/调试
故障 | 超时/非法状态/磁场异常/通信失败 | 节点状态必须通过CAN上报


1024线的实际分辨率 / 若把AB的“1024线/圈”按四倍频计数，则每转约4096个计数，单计数约0.0879°。这是“计数分辨率”，不是传感器绝对精度。你提供的KTH5502系列资料还给出了数字模式16 bit分辨率、AB模式DNL/噪声指标；最终AB1024料号应以对应版本的datasheet为准。

手部L103不要计算XYZ / 手部节点不知道当前人体坐标系、身体姿态、离合参考和机器人缩放参数，因此只上报“输入是什么”。XYZ统一交给H417-W，这样后续修改外骨骼尺寸或映射比例不需要修改手部固件。

节点时间一致性 / 不要求所有L103共用同一个硬件时钟，但必须在H417-W做“新鲜度”判断。推荐每个输入/关节节点都带seq，H417记录最近更新时间；超过阈值就把该数据标为stale，而不是继续使用最后一次数据却不知情。

为什么IK优于“按比例映射关节角” / 人体肩部/肘部三关节与机器人机械臂的关节轴、长度、零位、限位一般不相同。直接关节映射会把人体结构缺陷带到机器人结构里。Cartesian + IK允许机器人按照自身结构寻找最合适的关节组合，并可加入关节限位、速度限制、避奇异和“最接近上一时刻姿态”的代价函数。


IK模块 | 实现建议 | 关键约束
模型 | 先建立DH或POE模型 | 每个关节零位、正方向、长度、安装偏置必须实测
解算方式 | 若结构简单优先解析IK；否则采用数值IK | 数值法推荐Damped Least Squares / Jacobian
初值 | 上一周期关节角 q_prev | 目标是连续运动而不是每次从默认姿态重解
代价 | min ||q-q_prev||_W + λ||pose_error|| | W可用于限制某些关节变化
限位 | 求解前后都检查 | 硬限位/软件限位双层处理
无解 | 保持上一安全目标，必要时缓慢回安全位 | 绝不能把NaN/越界角直接发送到执行器
奇异点 | 监控Jacobian条件数或DLS阻尼 | 接近奇异点时降低速度/增大阻尼
双臂 | 先独立IK，再做双臂工作空间/碰撞检查 | 必要时加入共享约束


C620资料中的关键事实 / 你提供的C620说明书规定：0x200可同时控制1~4号电调，控制量范围-16384~+16384，对应-20~+20 A；反馈ID为0x200+电调ID，例如1号为0x201。反馈包含机械角0~8191、转速rpm、实际转矩电流和温度，默认发送频率1 kHz。建议H417-R在软件上把这些原始字段再包装成统一的MotorState。


项 | 建议基线 | 原因
无线节点数 | 穿戴端1个TX、接收机1个RX | 集中处理时序/重传/安全更容易
速率 | 先测试1 Mbps；若距离不足再评估250 kbps | 1 Mbps单包空口时间更短，适合较拥挤环境；250 kbps灵敏度更有余量但占空时间更长
更新率 | 100~200 Hz控制包为第一版目标 | 人体动作不需要1 kHz空口更新；留出重传和干扰余量
应用序号 | 16-bit seq | 丢包/重传后可以识别旧包
失败策略 | 超过超时阈值进入安全状态，同时扫描/切换备用信道 | 不要无限重传旧命令
信道策略 | 开机扫描候选信道，保存主/备信道 | 比赛现场需要应对其他无线设备
功率 | 从能稳定工作的较低功率开始 | 并非功率越高越好；近距离高功率会增加占频


故障 | 检测 | 动作
无线超时 | 最后有效包时间 | 停止更新机器人运动目标；底盘/关节控制器进入安全输出
关节节点掉线 | CAN heartbeat/seq超时 | 对应手臂禁止继续自由跟随；可保持当前安全位或停止
IMU异常 | 数据率/WHO_AM_I/范围/时间戳 | 禁止需要姿态变换的模式；退回简化映射或安全状态
IK无解 | 迭代失败/越限/NaN | 保持上次安全目标，不发送非法值
C620反馈异常 | 角度/温度/通信状态 | 按电机故障策略降级或停止
MCU任务卡死 | 独立看门狗 + task watchdog | 复位后进入FAULT，不自动恢复运动
按钮卡死/摇杆异常 | ADC stuck-at /范围检查 | 忽略异常输入，状态上报


强烈建议加入Deadman / 为了比赛和人体佩戴安全，建议至少预留一个“按住才允许机器人动作”的按钮。Toggle离合可以保留，但它不应承担唯一的安全功能。无线掉线、传感器异常、H417复位后，都应该默认不输出运动。
